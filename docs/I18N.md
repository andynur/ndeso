# I18N — Localization (EN + ID at launch)

## 1. Rules (non-negotiable)

1. **No hardcoded player-facing strings** in code. Use `t('key')` in UI and text keys in content data.
2. **`en` is the source locale.** Every key in `en` must exist in `id` (and future locales). CI fails on missing or extra keys (`bun run check:i18n`).
3. New UI text needs **both EN and ID** in the same PR. If you can't write good Indonesian, add the key with the prefix `[TODO-ID] ` in `id` and label the PR `needs-translation`. CI reports `[TODO-ID]` as a warning on branches and on `main`, and **fails on a release tag** (`refs/tags/*`) — untranslated strings may sit in the default branch while a translator catches up, but they must never ship.
4. Numbers, money, dates: always through `format.*`, never string concatenation.
5. Never build sentences from fragments (`t('you_got') + item + t('from')`). Use placeholders.

## 2. Files

```
packages/content/locales/
├── en/
│   ├── ui.json         # menus, HUD, settings, system messages
│   ├── items.json      # item/crop/tool names + descriptions
│   ├── npcs.json       # NPC names, titles, short bios
│   ├── glossary.json   # cultural terms (Kamus)
│   ├── calendar.json   # mangsa names and pertanda (signs)
│   └── tutorial.json
└── id/  (same file names, same keys)
packages/content/dialog/
├── en/<npc>.ink
└── id/<npc>.ink        # same knots/stitches/choice structure
```

- **Flat dotted keys** within a namespace file: `"hud.money": "Money"`. The namespace is the file name. Call it as `t('ui:hud.money')`, or `t('hud.money')` inside the `ui` default namespace.
- Key naming: `area.element.state` in lowercase snake_case segments: `settings.graphics.preset_low`, `shop.buy.confirm`.
- Keep keys semantic, not English text (`shop.buy.confirm`, not `are_you_sure_you_want_to_buy`).

## 3. Message format (small ICU subset)

Supported inside strings:
- Placeholders: `{name}`
- Plural: `{count, plural, one {# egg} other {# eggs}}` (uses `Intl.PluralRules(locale)`; Indonesian has only `other`, so ID strings may just use `{count} telur`)
- Select: `{gender, select, female {…} male {…} other {…}}` (rarely needed; Indonesian pronoun *dia* is neutral, so prefer neutral phrasing in EN too)

Examples:
```json
// en/ui.json
{ "ship.summary": "You earned {money} from {count, plural, one {# item} other {# items}}." }
// id/ui.json
{ "ship.summary": "Kamu mendapat {money} dari {count} barang." }
```
`{money}` is pre-formatted by the caller via `format.money(value)`.

## 4. Runtime API (`apps/client/src/i18n/`)

```ts
await i18n.init();                  // pick locale: saved setting → navigator.language startsWith('id') → 'en'
t('ui:shop.buy.confirm', { item: t('items:crop.cabai.name'), price: format.money(800) });
i18n.setLocale('id');               // hot switch; UI re-renders via signal
format.money(12500)                 // id: "Rp12.500"  en: "Rp12,500"  (Intl.NumberFormat, currency IDR, 0 decimals)
format.number(1234.5)
format.gameDate(day)                // takes the absolute day only; mangsa, weekday, pasaran and the
                                    // Hijri date are derived from it (ADR-0007), never passed in.
                                    // id: "Senin Legi · Mangsa Kapat hari ke-3"
                                    // en: "Monday (Legi) · Mangsa Kapat, day 3"
format.clock(minute)                // id/en: "15:40 · Ashar" — the prayer-time band is a label, not a gate

```
- Locale JSON loads lazily per namespace (`ui` at boot, the rest on demand) and is cached by the service worker.
- Typed keys: `tools/i18n/gen-types.ts` generates `I18nKey` union types from `en/*.json`, so a typo is a compile error.
- Missing key at runtime: dev builds show `⟦key⟧` and log a warning. Prod builds fall back to `en`, then to the key.

## 5. Content data

Content never contains prose, only keys:
```json5
// packages/content/data/crops.json5
{ id: 'cabai', nameKey: 'items:crop.cabai.name', descKey: 'items:crop.cabai.desc', musim: 'kemarau', growDays: 8, regrowDays: 3, seedPrice: 800, sellPrice: 700, origin: 'Baledono, Purworejo, Jawa Tengah' }
```
`check:content` verifies that every `*Key` exists in `en` (and so, via parity, in `id`).

## 6. Dialog (Ink)

- One `.ink` file per NPC per locale, with identical knot/stitch names and identical choice counts.
- Game logic (flags, friendship changes) lives in Ink **tags** or external functions that are the **same in both locales**. `tools/i18n/check-ink.ts` compares the compiled structure (knots, choice counts, tags).
- Writers may reword freely within a knot but must not add or remove branches in only one locale.

## 7. Translation style

| | EN | ID |
|---|---|---|
| Player address | "you" | *kamu* (never *Anda* in gameplay; *Anda* is allowed only in legal/privacy text) |
| Cultural nouns | Keep in Indonesian, italic in dialog, glossary entry | Normal |
| Tone | Warm, simple | *Santai tapi sopan* |
| Length | Baseline | Expect +20–30%. UI must allow it |
| Currency | "Rp12,500" | "Rp12.500" |
| Time | 24 h clock in both (`06:00`), matching the in-game clock style |  |

Keep a shared term base in `glossary.json` (both locales) so "sawah", "pasaran", and tool names are always the same.

## 8. Adding a new locale (e.g. `jv` Javanese, `su` Sundanese, `ms` Malay)

1. Copy `locales/en` → `locales/<code>`, translate.
2. Copy `dialog/en` → `dialog/<code>`, translate.
3. Add `<code>` to `SUPPORTED_LOCALES` in `packages/shared/src/i18n.ts` with its display name (in its own language) and `Intl` locale tag.
4. Run `bun run check:i18n`. No other code changes are needed (FR-084).

## 9. Fonts & glyphs

EN and ID both use the Latin script. Plus Jakarta Sans Latin + Latin Extended covers them. Future Arabic-script (Jawi) or other scripts would need a font fallback plan (out of scope for v1).
